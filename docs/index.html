      What the real tool tells you

      Output from whycant on a Linux machine. Every run answers the same three questions.

      $ whycant -u bob team/f
Can bob (uid 30033) read team/f?

  [ ok ]  drwxr-xr-x  root:root  /srv/wtest
  [DENY]  drwxr-x---  root:devs  /srv/wtest/team

  Why: bob is not the owner and not in group devs,
       so the 'other' bits apply, and they lack x.

  Narrowest fix first:
    1) setfacl -m u:bob:x /srv/wtest/team
       # only this user
    2) usermod -aG devs bob
       # every member of the group
    3) chmod o+x /srv/wtest/team
       # every user on the system
  Avoid chmod 777 and chmod -R.

  => Denied.

      • Where

        Each folder on the path gets a line. The first [DENY] is the one blocking access.

      • Why

        Which rule Linux applied: owner, group or everyone else, and which bit is missing.

      • Fix

        Ranked from one user to everyone. It never suggests chmod 777.

      For Linux on x86_64. The checksum step proves the file you downloaded is the one that was published.

      1. Download the program and its checksum

        wget https://github.com/Hennashakil/whycant/releases/download/v1.0/whycant-linux-x86_64 \
     https://github.com/Hennashakil/whycant/releases/download/v1.0/SHA256SUMS

      2. Verify it

        You should see whycant-linux-x86_64: OK. If it says FAILED, delete the file and don’t run it.

        sha256sum -c SHA256SUMS

      3. Install it

        chmod +x whycant-linux-x86_64
sudo mv whycant-linux-x86_64 /usr/local/bin/whycant

      Usage

      whycant [OPTION] [PATH]. Both are optional: with no path, it checks the folder you are in.

      CommandQuestion it answers
      whycantCan I read the folder I am in?
      whycant /etc/hostsCan I read this file?
      whycant -w notes.txtCan I edit it?
      whycant -x ./backup.shCan I run it?
      whycant -c /opt/myappCan I create it here?
      sudo whycant -u www-data /var/www/htmlCan another user reach it?

      Exit codes: 0 allowed, 1 denied, 2 error, so scripts can act on the result.

      Built to give safe advice

      whycant only reads. It never changes a file, and some locks it will not help you open.

      Stop

      Protected files

      Password, key and admin files such as /etc/shadow, sudoers, SSH keys and /root get a stop instead of a fix.

      Stop

      Root-level groups

      It never suggests joining docker, disk, sudo or similar groups, where membership is as good as root. Raw disks are blocked too.

      sudo

      Root only when needed

      It runs as you. If it can’t see further, it prints the exact sudo command, and under sudo it still checks for you, not for root.

      How Linux decides

      Every folder on the way needs x, permission to pass through. At the end, you need what you asked for: r, w or x. At each step Linux asks four questions, in order, and the first match wins:

      1. Is the user root? Then allowed, except running a file with no x bit.
      2. Does the user own it? Then only the owner bits count.
      3. Is the user in its group? Then only the group bits count.
      4. Otherwise, the bits for everyone else count.

      Rule 2 surprises people: if you own a file but the owner bits are empty, Linux never falls back to the group bits. Try alice in the demo above, or the “Locked out of my own file” example.
